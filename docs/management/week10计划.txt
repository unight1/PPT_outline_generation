================================================================================
  第 10 周 — 工作计划（总览，不是分工表）
================================================================================
  说明：本文档说明本周要做什么、先做什么后做什么、怎样算做完。
        四人具体认领见 docs/management/week10分工.txt。
  契约：docs/api_contract_v1.md；新增字段先定名（见第七节）再改代码。
  不包含：评测报告、答辩材料、全栈 Docker；第 9 周已交付内容（见第六节）。

================================================================================
  一、本周目标（一句话）
================================================================================

  把系统从「能跑通」变成「好用」：前端先优化现有界面并预留新功能位置，
  后端补齐长文档、智能澄清、检索与上传等能力，最后前后端接上线并联调。

================================================================================
  二、整体节奏（先做什么、后做什么）
================================================================================

  阶段 A — 前端先行（不等 week10 新接口）
  ─────────────────────────────────────
  · 优化现有 v1 流程的界面与文案（创建 → 澄清 → 骨架 → 按页生成 → 结果）。
  · 结果页改为「一页一屏」翻页查看，不要所有页堆成一长串表单。
  · 生成中与结果尽量共用同一套「单页」展示组件。
  · 为新功能先做界面占位（历史列表、上传区、章节分组、文档分析中等），
    后端未就绪时可 Mock 或灰态提示，不挡主流程。

  阶段 B — 后端并行（与阶段 A 可同时进行）
  ─────────────────────────────────────
  · 长文档：模型预处理 + 按页生成真正用上文档。
  · 澄清：用大模型生成 3～5 道题（前端仍全部用文本框作答）。
  · 检索策略统一；可选上传文件 + 按任务建库。
  · 章节：契约 + 骨架/大纲带章节结构。

  阶段 C — 对接与打磨（后端就绪后）
  ─────────────────────────────────────
  · 把阶段 A 的占位逐个换成真实接口与数据。
  · 任务历史、证据/低可信提示、章节分组、上传与高级检索选项全开。
  · 全员跑通短主题 + 长文档两条完整路径（见第五节）。

  示意：

    阶段 A（前端）     阶段 B（后端）        阶段 C（对接）
    ─────────────    ─────────────       ─────────────
    导航/创建/澄清    文档预处理           历史列表接线
    一页一屏结果      模型出澄清题         「分析文档」真状态
    生成中单页预览    按页用文档           章节 UI 接线
    样式+组件拆分     检索策略/上传        上传与证据区完善
    各类占位壳        章节契约+后端

================================================================================
  三、阶段 A — 前端（先做）
================================================================================

  【现状问题】
    界面偏乱、像 Demo；步骤条与真实流程不一致；结果页字段堆叠难读；
    澄清与生成中/失败挤在一屏；无任务历史入口。

  【A1】全局导航与基础体验（优先）
    要做：
      · 步骤条固定 4 步：基本信息 → 回答问题 → 确认骨架 → 查看大纲。
      · 去掉「前端 Demo」等调试口吻；错误提示尽量靠近对应输入框。
    验收：未参与开发的同学能不看 README 走完创建到进骨架。

  【A2】创建任务页
    要做：
      · 标题改为「创建演示任务」（与澄清区分）。
      · 分区：主题与场景 / 材料类型 / 高级选项（可折叠）。
      · 「检索深度」改为大白话：资料少查 / 平衡 / 多查引用。
      · 长文档：字数统计；主按钮如「下一步：回答几个问题」。
    验收：短主题、长文档两种创建都清晰。

  【A3】澄清页
    要做：
      · 独立一屏，不与生成进度、失败信息混排。
      · 每题一个文本框；预填答案（如页数）要显眼。
      · 提交后只保留一条路径进入骨架，去掉重复按钮。
    验收：提交澄清后稳定进入骨架页。

  【A4】结果页 · 大纲工作台（核心）
    要做：
      · 一次只展示当前页：标题、核心结论、要点、讲者备注、配图建议、页级小结。
      · 左侧（或顶部）页列表 + 上一页 / 下一页（或点击跳转）。
      · 进入结果时默认第 1 页；保留保存、单页重做、复制/下载 Markdown。
    验收：8 页以上大纲能靠翻页浏览，无需滚很长一屏。

  【A5】生成中预览
    要做：
      · 页状态条：已完成 / 生成中 / 失败。
      · 当前页大图预览，组件尽量与 A4 共用（SlidePanel）。
      · 全部完成后进入结果工作台。
    验收：按页生成过程中能看到已完成页内容。

  【A6】骨架页（基础优化）
    要做：
      · 可先保持现有表单编辑。
      · 按页生成前的选项放入折叠「高级选项」（深度、联网、并发、强制刷新）。
    验收：能改骨架并触发按页生成。

  【A7】样式与工程
    要做：
      · 统一主色、间距、卡片与按钮层级。
      · 拆分 App.vue（建议：TaskSteps、CreateForm、ClarificationForm、
        SkeletonEditor、SlideDeckView、TaskSidebar 等）。
    验收：代码结构便于阶段 C 接线。

  【A8】新功能界面占位（先壳后线）
    占位项          界面表现                          阶段 C 再接
    ─────────      ─────────────────────────────    ─────────────
    任务历史        侧栏或首页「最近任务」区域          GET /api/tasks
    文档分析中      长文档创建后 loading 文案           第 B1 项预处理
    上传文档        「上传文件（即将支持）」灰态        第 B5 项上传 RAG
    章节分组        页列表旁「按章」折叠（无数据则扁平）  第 B4 项 chapters
    检索高级        优先我的文档 / 来源质量（可先禁用）  第 B3 项 policy

  【阶段 A 完成判定】
    短主题全流程界面顺畅；结果页一页一屏；占位不报错、不挡主流程。

  【主要文件】
    frontend/src/App.vue
    frontend/src/components/（建议新建）
    frontend/src/types/task.ts、frontend/src/api/mockApi.ts

================================================================================
  四、阶段 B — 后端（与阶段 A 并行）
================================================================================

  【B1】长文档 · 模型预处理（必做）
    问题：目前只有规则切块和关键词，模型没有「读懂」全文。
    要做：
      · source_type=long_document 且提交了 document_text 时，创建任务后调用
        大模型 1～2 次，输出 JSON 写入 document_profile：summary、key_points、
        可选 suggested_focus；不编造文中没有的内容。
      · 超长文：分段摘要再合并；失败则降级为规则 profile，流程继续。
    验收：GET 任务可见 summary/key_points；骨架标题与文档主题相关。
    文件：document_llm.py（或扩 document_processing.py）、tasks.py、skeleton.py

  【B2】长文档 · 按页生成用上文档（必做）
    问题：按页生成时未注入文档片段，长文档模式只帮了一半。
    要做：
      · 每页检索 query、LLM 输入带上与本页相关的 segment / 要点（用 B1 的 profile）；
      · 优先用户文档材料，再考虑联网。
    验收：长文档全流程生成内容与粘贴正文明显相关。
    文件：page_generation.py（可参考 orchestration.py）

  【B3】模型生成澄清题（必做）
    问题：澄清题为固定模板，与主题/文档无关，且可能与创建页重复提问。
    要做：
      · 创建任务后调一次大模型，生成 3～5 题 JSON（question_id、prompt、可选 answer）；
      · 规则过滤已填项（如已填听众则不问听众水平）；失败则 2～3 道保底题。
      · 长文档题需结合文档摘要；前端仍全部文本框作答。
    验收：不同主题题目措辞不同；USE_REAL_LLM=false 不崩。
    文件：clarification.py、tasks.py

  【B4】PPT 章节（契约 + 后端）
    要做：
      · 更新契约：outline / skeleton 增加 chapters（或每页 chapter_id）；
      · 骨架生成输出章节划分；合并大纲时保留章节。
    验收：API 返回结构含章节；至少 2 章多页可解析。
    文件：api_contract_v1.md、skeleton.py、page_generation.py

  【B5】用户上传 + 任务级 RAG
    要做：
      · 上传接口（先做 .md / .txt 一种即可）；按 task_id 建向量库；
      · 按页检索先查用户文件，再全局库 / Tavily。
    验收：上传含专有名词的文件，生成内容能体现该说法。
    文件：tasks.py 或 routes/documents.py、retrieval/

  【B6】检索策略统一
    要做：
      · 定义 retrieval_policy 写入 runtime；按页生成请求可传；
      · v1 按页路径补齐来源过滤等（与第 9 周 RAG 能力对齐，避免 v0 有、v1 无）。
    验收：改「查多/查少」后引用数量有可见差别。
    文件：tasks.py、page_generation.py、config.py

  【建议后端顺序】
    B1 → B3 → B2 → B6 →（B4 与 B3 可协调契约）→ B5

================================================================================
  五、阶段 C — 前后端对接（后做）
================================================================================

  在阶段 A 占位、阶段 B 就绪后逐项接线：

    C1  任务历史侧栏 ↔ GET /api/tasks，按 status 跳进澄清/骨架/结果
    C2  澄清页 ↔ 模型出题（仍全文本框）
    C3  长文档 ↔ 真实「分析文档」状态与失败提示
    C4  结果单页视图 ↔ 本页证据、低可信要点（page_evidence_map / meta）
    C5  章节占位 ↔ chapters 分组展示与编辑
    C6  上传区 ↔ 上传 + 按页优先检索
    C7  骨架高级选项 ↔ retrieval_policy 全字段
    C8  骨架页左右分栏（若 A6 未做则此时做）

  【阶段 C 完成判定】
    第五节两条路径全部跑通；占位无「即将支持」残留（或仅保留明确未做项）。

================================================================================
  七、需先约定的字段（定名后写入 api_contract_v1.md）
================================================================================

  1. document_profile（B1，长文档）
       summary, key_points, suggested_focus? ；保留 segments 等规则字段。

  2. chapters（B4）
       chapters[] { chapter_id, title, slide_ids[] } 或 slide.chapter_id（二选一）。

  3. clarification.questions（B3）
       question_id, prompt, answer；无 options / 题型字段。

  4. retrieval_policy（B6）
       retrieval_depth, tavily_enabled, prefer_user_doc, source_quality,
       force_refresh, enable_fallback_deepen 等；未传则用 .env 默认。

  5. attachments（B5）
       { document_id, filename, status, chunk_count? }；status: pending|ready|failed

  6. 任务列表 GET /api/tasks
       列表项含 task_id, input.topic, status, updated_at 即可。

  约定：主责人先改契约 § 补充 → 全组确认 → 前后端实现。

  九、整体验收（阶段 C 结束后）

  真实后端 + 真实大模型（有 key 时）跑通：

  路径 A — 短主题
    4 步界面创建 → 澄清（文本框）→ 骨架 → 按页生成（单页预览）

    粘贴 2000 字以上 → 分析文档完成 → 模型澄清题 → 骨架 → 按页生成
    → 内容与原文相关；若 B5 完成再走上传路径。

================================================================================
  第 10 周 — 四人分工（2 前端 + 2 后端 + 组长对接）
================================================================================
  依据：docs/management/week10计划.txt（阶段 A / B / C）
  契约：docs/api_contract_v1.md §9（v1.1.0 扩展字段已定名，直接按契约实现）
  原则：四人并行、各自可 Mock / 本地 API 自测；**阶段 C 全部由组长完成**，他人勿改对接 PR。

================================================================================
  分工一览
================================================================================

  角色     | 代号   | 本周交付（可独立验收）
  ---------|--------|----------------------------------------------------------
  后端 1   | BE-1   | B1 长文档 LLM 预处理 + B2 按页用上文档 + B4 章节（后端）
  后端 2   | BE-2   | B3 模型澄清题 + B6 检索策略 + B5 上传与任务级 RAG
  前端 1   | FE-1   | A1～A3、A6：导航 / 创建 / 澄清 / 骨架（主流程前半段）
  前端 2   | FE-2   | A4～A5、A7～A8：结果翻页 / 生成预览 / 样式拆分 / 占位壳

  对应计划：BE-* → 第四节阶段 B；FE-* → 第三节阶段 A；LEAD → 第五节阶段 C。

================================================================================
  后端 1（BE-1）— 长文档链路 + 章节结构
================================================================================

  依赖：仅依赖契约 §9.1、§9.2；不依赖 BE-2、前端分支。

  【BE-1a】B1 · 长文档模型预处理
    要做：
      · source_type=long_document 且含 document_text 时，创建后调 LLM 1～2 次；
      · 写入 input.document_profile：summary、key_points、可选 suggested_focus；
      · 与规则字段（segments、char_count、keywords 等）合并，不删规则键；
      · 超长文分段摘要再合并；失败降级规则 profile，任务可继续；
      · 可选：runtime.document_analysis_status（pending/running/done/failed）。
    文件：
      backend/app/services/document_llm.py（新建，或扩 document_processing.py）
      backend/app/api/routes/tasks.py
    验收：
      · GET 任务（或内部读 task）可见 LLM 的 summary/key_points；
      · USE_REAL_LLM=false 不崩；失败仍有规则 profile。

  【BE-1b】B2 · 按页生成用上文档
    要做：
      · page_generation：每页 query / prompt 注入与本页相关的 segment、profile 要点；
      · 检索优先用户文档（prefer_user_doc），再全局库 / Tavily；
      · 不每页塞全文。
    文件：
      backend/app/services/page_generation.py
      backend/tests/test_page_generation.py（至少 1 个长文档相关用例）
    验收：
      · 长文档任务走完按页生成后，要点与粘贴正文明显相关；
      · 无 BE-2 上传时也能仅靠 document_text 通过。

  【BE-1c】B4 · 章节（仅后端）
    要做：
      · 骨架生成输出 outline.chapters[]（chapter_id、title、slide_ids）；
      · 按页 merge 时保留章节；slides 可带 chapter_id 与 chapters 一致；
      · GET 任务 outline / outline_skeleton 含章节结构。
    文件：
      backend/app/services/skeleton.py
      backend/app/services/page_generation.py（merge）
      backend/app/api/routes/tasks.py
      backend/tests/（骨架或 outline 含 chapters 的断言）
    验收：
      · API 返回至少 2 章、多页，JSON 符合契约 §4.3、§9.2；
      · **不再改** api_contract_v1.md（契约已由组长定稿）。

  自测路径（无需前端）：
    Postman / Swagger：POST 长文档任务 → GET profile → 澄清提交 → skeleton/generate
    → slides/generate → 检查 outline 内容与 chapters。

  与 BE-2 接口约定：
    · document_profile 键名以契约 §9.1 为准；BE-2 出题可读 summary，无则忽略。
    · chapters 字段以契约为准；BE-2 检索、上传不改章节结构。

================================================================================
  后端 2（BE-2）— 澄清 + 检索策略 + 上传 RAG
================================================================================

  依赖：契约 §9.3、§9.4、§9.5、§3.6；document_profile 有则用、无则降级（不阻塞 BE-1）。

  【BE-2a】B3 · 模型生成澄清题
    要做：
      · 创建任务后调 LLM 一次，输出 3～5 题 JSON（question_id、prompt、answer 可预填）；
      · 规则过滤已填项（听众、时长等）；失败 2～3 道保底题；
      · 长文档结合 document_profile.summary（无则用规则摘要）；
      · **禁止** options / type 等选择题字段。
    文件：
      backend/app/services/clarification.py（新建）
      backend/app/api/routes/tasks.py
      backend/tests/test_api_tasks.py（创建任务后 questions 形状）
    验收：
      · 不同 topic 题干不同；USE_REAL_LLM=false 有保底题；
      · PATCH clarification 仍与 v0 兼容。

  【BE-2b】B6 · 检索策略统一
    要做：
      · POST .../slides/generate 接受 retrieval_policy，合并写入 runtime.retrieval_policy；
      · page_generation / 单页 regenerate 读取 policy（深度、联网、prefer_user_doc、
        source_quality、force_refresh、enable_fallback_deepen）；
      · v1 按页路径补齐来源质量过滤（与第 9 周能力对齐，不重复造 query 文案轮子）。
    文件：
      backend/app/api/routes/tasks.py
      backend/app/services/page_generation.py
      backend/app/config.py、.env.example
    验收：
      · 改 retrieval_depth / source_quality 后引用数量或来源有可见差别；
      · 未传字段走 .env 默认。

  【BE-2c】B5 · 用户上传 + 任务级 RAG
    要做：
      · POST /api/tasks/{task_id}/documents/upload（先支持 .md 或 .txt 一种）；
      · 按 task_id 建向量 collection；input.attachments[] 更新 status；
      · 按页检索：先任务附件库，再全局库 / Tavily。
    文件：
      backend/app/api/routes/tasks.py 或 routes/documents.py
      backend/app/retrieval/（index / retriever）
      .env.example
    验收：
      · 上传含专有名词的文件，生成内容能出现该表述；
      · attachments 项含 document_id、filename、status、chunk_count（ready 时）。

  自测路径（无需前端）：
    · BE-2a：POST short_topic → GET questions。
    · BE-2b：slides/generate 带不同 policy → 对比 evidence_catalog。
    · BE-2c：upload → slides/generate → 命中上传关键词。

  与 BE-1 接口约定：
    · 不修改 document_profile / chapters 的写入逻辑；只读 profile.summary 用于出题。
    · retrieval_policy 键名以契约 §9.4 为准。

================================================================================
  前端 1（FE-1）— 主流程前半段（创建 → 澄清 → 骨架）
================================================================================

  依赖：现有 v1 API + Mock；**不接** week10 新接口真数据（阶段 C 由组长接）。

  【FE-1a】A1 · 全局导航与基础体验
    要做：
      · TaskSteps：固定 4 步（基本信息 → 回答问题 → 确认骨架 → 查看大纲）；
      · 去掉 Demo 口吻；错误提示靠近对应控件。
    验收：Mock 下能从创建走到骨架、再到结果入口（结果页可由 FE-2 提供组件）。

  【FE-1b】A2 · 创建任务页
    要做：
      · 标题「创建演示任务」；分区：主题与场景 / 材料类型 / 高级选项（折叠）；
      · 检索深度大白话（资料少查 / 平衡 / 多查引用）；
      · 长文档：字数统计；主按钮「下一步：回答几个问题」。
    验收：short_topic、long_document 两种表单清晰可用。

  【FE-1c】A3 · 澄清页
    要做：
      · 独立一屏；每题一个文本框；预填 answer 高亮；
      · 提交后单一入口进骨架；不与「生成中 / 失败」混排（分路由或分块）；
      · questions 仍用 question_id、prompt、answer（Mock 里可写死 3 题，不接模型）。
    验收：提交澄清后稳定进入骨架视图。

  【FE-1d】A6 · 骨架页（基础）
    要做：
      · 保持现有列表编辑骨架；
      · 「高级选项」折叠：深度、联网、并发、强制刷新（控件可先绑 Mock / 本地 state，
        **不必**等 retrieval_policy 真接口）；
      · 触发按页生成按钮与进度跳转（生成中 UI 用 FE-2 的 SlidePanel 若已抽组件）。
    验收：Mock 下可改骨架并进入「生成中」状态。

  主要文件：
    frontend/src/App.vue（或拆出 TaskSteps、CreateForm、ClarificationForm、SkeletonEditor）
    frontend/src/types/task.ts（仅增 FE-1 需要的类型）
    frontend/src/api/mockApi.ts、frontend/src/mocks/

  自测：VITE_USE_MOCK_API=true，走完 创建 → 澄清 → 骨架，不依赖 BE-*。

  与 FE-2 约定：
    · 公共组件放 frontend/src/components/，命名由 FE-2 定目录亦可，但接口先对齐：
      TaskSteps、CreateForm、ClarificationForm、SkeletonEditor。
    · 进入「查看大纲」路由后交给 FE-2 的 SlideDeckView / GeneratingView。

================================================================================
  前端 2（FE-2）— 结果工作台 + 生成预览 + 样式与占位
================================================================================

  依赖：Mock 含 outline_skeleton、outline、progress（含 slide_id/completed/failed）；
        不接 GET /api/tasks 真列表、上传、章节真数据（组长阶段 C 接）。

  【FE-2a】A4 · 结果页 · 大纲工作台（核心）
    要做：
      · SlideDeckView：左侧页列表 + 当前页单屏（标题、key_message、bullets、
        speaker_notes、visual_suggestion、takeaway）；
      · 上一页 / 下一页；默认第 1 页；保留保存、单页重做、Markdown 导出。
    验收：Mock 8 页以上仅靠翻页浏览，无长滚动表单。

  【FE-2b】A5 · 生成中预览
    要做：
      · 页状态条（已完成 / 生成中 / 失败）；当前页大图预览；
      · 与 A4 共用 SlidePanel / SlideDeckView 子组件；
      · 读 progress.slide_id、completed、failed（Mock 模拟增量）。
    验收：Mock 按页生成过程中可看到已完成页内容。

  【FE-2c】A7 · 样式与工程
    要做：
      · 统一主色、间距、卡片与按钮；
      · 拆分 App.vue：SlideDeckView、GeneratingView、TaskSidebar（占位）等；
      · FE-1 拆出的表单组件样式与 FE-2 一致。
    验收：目录清晰，便于组长接线；合并时尽量减少 App.vue 冲突。

  【FE-2d】A8 · 新功能占位壳（仅 UI）
    占位项              | 表现
    --------------------|------------------------------------------
    任务历史            | 侧栏「最近任务」列表 UI，Mock 2 条，点击仅 console 或 toast
    文档分析中          | 长文档创建后 spinner +「正在分析文档…」
    上传文档            | 灰态「上传文件（即将支持）」
    章节分组            | 页列表「按章」折叠；Mock chapters 可展示，无数据则扁平列表
    检索高级            | 优先我的文档 / 来源质量（disabled + 说明文案）

    验收：占位不报错、不挡 FE-1 主流程；文案标明「对接中」即可。

  主要文件：
    frontend/src/components/SlideDeckView.vue（等）
    frontend/src/App.vue（结果 / 生成中路由）
    frontend/src/types/task.ts（Slide、Progress、Outline、Chapter）
    frontend/src/mocks/mockTask.ts（含多页 + 可选 chapters）

  自测：VITE_USE_MOCK_API=true，从骨架点生成 → 生成中 → 结果翻页全流程。

  与 FE-1 约定：
    · chapters 展示按契约 §9.2 Mock，不擅自改字段名。
    · 证据区、低可信样式可先写死样式，数据用 Mock page_evidence_map。
